# ARA–DDDAS: adversarial demand-response manipulation

Code for the computational study of *Adversarial Demand Response Manipulation: A Bayesian ARA–DDDAS Framework for Sequential Outlier Detection and Load Forecasting in Smart Grid Reliability* (Reliability Engineering & System Safety, manuscript JRESS-D-26-05172, revision R1).

The code simulates one-week episodes of a sequential game between a defender (the utility) and one potentially strategic demand-response participant, on real ERCOT system load and prices with synthetic participant-level consumption. Five defender strategies are compared on common random numbers: no defense, a static rule, ARA without learning, ARA–DDDAS, and a complete-information benchmark. Equation names in the code comments refer to the `\label`s of the manuscript.

## Requirements

Python 3.10+ with `numpy`, `scipy`, `pandas`, `openpyxl`, `xlrd` and `matplotlib`. `statsmodels` is needed only for `tests/sampler_validation.py`.

## Data

The ERCOT files are public and not included. Download them from ERCOT and place them in one folder, then point `RESS_DATA_DIR` to it (default: the parent folder of this repository).

| Data | Source | Files (2015–2017 in the folder itself, 2022–2025 in `ercot_recent/`) |
|---|---|---|
| Hourly native load by weather zone | [ERCOT load archive](https://www.ercot.com/gridinfo/load/load_hist) | `native_load_2015.xls`, `native_Load_2016.xlsx`, `native_Load_2017.xlsx`, `ercot_recent/Native_Load_20{22..25}.xlsx` |
| Real-time settlement point prices (report 13061) | [ERCOT market prices](https://www.ercot.com/mktinfo/prices) | `rpt.00013061.0000000000000000.RTMLZHBSPP_{year}.xlsx` |

`data.py` handles the format differences between years (see its docstring). `python3 data.py` prints the summer summary (Table 2 of the manuscript).

## Running

```bash
python3 calibrate.py              # offline calibration for the five evaluation summers (about 4 min each)
python3 tests/acceptance.py       # acceptance tests on one 2017 check episode
python3 run_all.py B              # version B: 252 base + 396 sensitivity episodes (checkpointed, resumable)
python3 tests/longchain_check.py  # fixed draws vs. long-chain re-estimation
python3 tables.py B               # tables as CSV in tables/B/
python3 tables_tex.py             # LaTeX tables and number macros for Section 7.4 (RESS_TEX_DIR)
```

`rerun_all.sh` runs the whole sequence. Calibrations and episode set-ups are cached in `cache/` (not tracked). With 8 processes, version B takes about 30 minutes.

## Layout

| File | Content |
|---|---|
| `config.py` | all settings (manuscript Section 7.3); a run is a copy of `BASE` with overrides |
| `data.py`, `generator.py` | ERCOT data; synthetic participant consumption (`eq:generator`) |
| `detection.py` | Bayesian Gaussian mixture, tail probability, imputation (Section 4.1) |
| `forecasting.py` | seasonal ARIMA state-space model: Gibbs sampler, Kalman filter, forecast weights (Section 4.2) |
| `reliability.py` | event rule, forecast-error distribution, LOLP, exposure and reliability terms |
| `attacker.py`, `defender.py` | attacker belief and decision; ARA decision and type-belief update (Sections 5–6) |
| `calibrate.py`, `diagnostics.py` | offline calibration per summer; R-hat and effective sample size |
| `episode.py` | one episode, all strategies, per-interval order of moves (Section 3) |
| `run_all.py` | batch runs of experiment versions A, B, C |
| `tables.py`, `tables_tex.py` | result tables, paired bootstrap, LaTeX output |
| `figures_framework.py` | Figures 1 and 2 of the manuscript |
| `tests/` | acceptance tests, design checks, sampler validation, robustness checks, long-chain check |
| `results/` | version B and long-chain results (one CSV per episode, seed, true type) |
| `logs/` | outputs of the tests and checks |

## Reproducibility

Seeds are fixed in `config.py` and in the episode runner; all strategies of a replicate share the consumption paths, perception noise and calibration draws. Every number in Section 7.4 of the manuscript is generated by `tables_tex.py` from the files in `results/`.
